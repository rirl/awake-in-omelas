== Status

*Status:* Active Development (Bootstrap Phase)

This document is the authoritative architectural TODO for the Federated AI Platform implementation.

Its purpose is to record architectural intent, implementation milestones, validation checkpoints, and future work while preserving the provenance of design decisions within Git.

== Objective

Develop a vendor-neutral AI workbench that:

* Uses Open WebUI as the permanent user interface.
* Uses the OpenAI Platform API with pay-as-you-go billing.
* Supports multiple commercial AI vendors through API keys.
* Supports local/private inference using Ollama, vLLM, and future GPU infrastructure.
* Integrates Model Context Protocol (MCP) servers for secure access to repositories, databases, and project tooling.
* Allows AI to reason directly over Git-managed project knowledge.

== Architectural Principles

=== Stable User Interface

Open WebUI becomes the permanent AI workbench.

Model providers become interchangeable implementation details.

=== Vendor Independence

The platform should support multiple AI providers simultaneously.

Current provider:

* OpenAI Platform API

Planned providers:

* Anthropic
* DeepSeek
* Google
* Mistral
* Groq
* OpenAI-compatible endpoints

=== API Billing

Primary model access uses:

* OpenAI Platform account
* OpenAI API key
* Pay-as-you-go billing

A ChatGPT subscription remains valuable for research, experimentation, and ChatGPT-specific capabilities, but it is not required to operate Open WebUI.

=== MCP Boundary

MCP servers provide controlled access to project resources.

Initial servers include:

* Filesystem
* Git
* Databases
* Project-specific tooling

Filesystem access defaults to read-only.

Read-write access is enabled only on isolated feature branches during controlled editing sessions.

=== Repository as Memory

The long-term objective is for the Git repository—not conversational history—to become the authoritative project memory.

AI should reason over:

* Canon entries
* Provenance
* Architecture documents
* Git history
* TODO documents
* Project artifacts

rather than relying upon conversational recall.

== Architectural Provenance

The platform architecture is intentionally developed through incremental, validated milestones.

Each milestone should leave behind:

* Git commits
* Git checkpoint tags
* Updated architectural documentation
* Implementation artifacts
* Validation evidence

Together these form the architectural provenance of the platform, recording not only *what* was implemented, but *why*, *how*, and *when*.

== Long-Term Vision

Open WebUI becomes the permanent AI workbench.

Repositories become the permanent project memory.

MCP servers become reusable infrastructure.

AI providers become interchangeable computational resources.

The platform should continue functioning even as AI vendors, pricing models, subscription models, and deployment mechanisms evolve.
